# アクティカウンター 実装指示書

## 1. 目的

アクティメソッドのタイピング学習結果を検知し、Chrome 拡張機能内で当日の学習回数と手動ストップウォッチを管理する。

本書は、実装開始時にそのまま作業へ移れる粒度の仕様・設計・受け入れ条件を定める。

## 2. 確定した仕様

### 対象環境

- デスクトップ版 Google Chrome のみを対象とする。
- Manifest V3 を使用する。
- カウントと履歴は `chrome.storage.local`、ブラウザセッション中だけ必要なタブ状態とストップウォッチ状態は `chrome.storage.session` に保存する。サーバー送信・ログインユーザーとの紐付け・同期は行わない。
- Chrome プロファイル単位でデータを管理する。同じプロファイルを使うユーザー間ではデータを共有する。

### 対象 URL

カウンターとストップウォッチのパネルを表示する URL は次の範囲とする。

- `https://acti-island.com/typing`
- `https://acti-island.com/typing/` 以下の任意のパス

Chrome の `matches` だけに頼らず、コンテンツスクリプト側でも `location.pathname === "/typing" || location.pathname.startsWith("/typing/")` を確認する。

### カウンター

- 対象 URL では、結果ページでなくても初回は画面右上に固定パネルを表示する。
- パネルには「今日の回数」と現在値を表示する。
- 表示は `現在値 / 目標回数` とし、目標回数の初期値は 10 回とする。
- 目標回数は設定として 1〜100 の整数へ変更でき、日付変更や Chrome 再起動後も保持する。
- 目標回数は表示上の目標だけに使う。目標到達時の通知や色変更は行わず、現在値が目標を超えた場合も `15 / 10回` のようにそのまま表示する。
- カウントの最大値は目標回数と独立して従来どおり 100 回とする。
- 100 回に達した後の自動カウントは無視し、100 回のままにする。通知は表示しない。
- 初期値は 0 回とする。
- 拡張機能のツールバーアイコンからポップアップを開き、0〜100 の任意の整数を「開始回数」として保存できるようにする。
- 開始回数の保存は当日の現在カウントへ即時反映する。
- 開始回数の変更は履歴へ一切記録しない。履歴上の自動カウント数も変更しない。
- 日次リセット後の現在カウントは必ず 0 回とする。開始回数を翌日に引き継がない。

### パネルのドラッグ移動

- パネルのヘッダーをドラッグすると、対象ページ内の任意の位置へ移動できる。
- ドラッグできることを示す移動カーソルをヘッダーへ表示し、ドラッグ中はカーソル表示を切り替える。
- ヘッダー内の歯車ボタンではドラッグを開始せず、クリック操作を優先する。
- ドラッグ中はパネル全体がビューポート内に収まる範囲へ移動を制限する。
- 保存位置がない初回表示は、従来どおり画面上端・右端から 16px の位置とする。
- ドラッグ終了時にパネル左上の座標を `chrome.storage.local` へ保存し、ページ遷移や Chrome 再起動後も保持する。
- 保存位置はすべての対象ページ・タブで共通とし、別タブへの反映はドラッグ終了後のストレージ変更通知で行う。ドラッグ中の即時同期は行わない。
- ウィンドウサイズの変更や、保存時と異なる画面サイズでパネルが画面外へ出る場合は、表示時またはリサイズ時に画面内へ自動補正して補正後の位置を保存する。
- 位置を初期位置へ戻す専用機能は設けない。

### ストップウォッチ

- 対象 URL で初回は画面右上に表示されるカウンターパネル内へ、経過時間と「開始」「停止」「リセット」ボタンを表示する。
- 操作は対象ページ上のパネルだけで行い、拡張機能ポップアップにはストップウォッチ操作を追加しない。
- ストップウォッチは全タブで共有する 1 つのタイマーとする。どの対象タブから操作しても、すべての対象タブへ同じ経過時間と実行状態を反映する。
- 経過時間は `時:分:秒`（例：`01:23:45`）で表示し、24 時間を超えても時間を累積表示する。
- 表示は 1 秒ごとに更新する。時間は 1 秒ずつ加算して保存せず、開始時刻と現在時刻の差分から算出し、タブ休止中もずれないようにする。
- 初期状態は停止中の `00:00:00` とする。
- 初回は「開始」を押すと 0 秒から計測を開始する。
- 計測中は「開始」を無効、「停止」を有効、「リセット」を無効にする。
- 「停止」を押すとその時点の累積経過時間を保持する。停止中は「開始」の文言を「再開」に切り替え、「停止」を無効、「リセット」を有効にする。
- 「再開」を押すと、保持している累積経過時間から計測を続ける。
- 「リセット」を押すと、Shadow DOM 内にサイトのデザインへ合わせた独自確認モーダルを表示する。確認後にだけ `00:00:00` へ戻し、「再開」を「開始」へ戻す。キャンセル時は何も変更しない。
- リセットしても、すでに保存されたストップウォッチ履歴は削除しない。
- ページ遷移、対象タブの終了、Manifest V3 サービスワーカーの停止が発生しても、Chrome が起動している間は停止操作まで計測を継続する。
- Chrome の終了、拡張機能の更新・再読み込みでは実行状態と未リセットの経過時間を引き継がない。実行中だった未停止時間は履歴へ保存せず破棄し、次回は `00:00:00` の停止状態から始める。
- 日付が変わってもストップウォッチは停止・リセット・日別分割せず、ユーザーが停止するまで 1 回の計測として継続する。
- 日付をまたいだ計測履歴は、開始日ではなく停止した日の履歴へ保存する。

「停止」を押すたびに、停止日時とその時点の累積経過時間を新しい履歴として保存する。たとえば 10 分で停止し、その後再開して累積 15 分で停止した場合は、10 分と 15 分の 2 件を保存する。

### 結果ページの検知とカウント

- ページ内に「今回のタイピング結果」が表示されていることを結果ページの条件とする。
- サンプルでは `.title_text-result` 内に該当文言が存在するため、まず同要素を検査する。
- サンプルと将来の軽微な DOM 差分に備え、必要に応じて見出し要素のテキストもフォールバック検査する。ただし、ページ全体の単純な文字列検索だけにはしない。
- 通常のページ読み込みでは、コンテンツスクリプトの初期実行時（`document_idle`）に一度検知する。
- 戻る・進む操作で Back/Forward Cache からページが復元された場合は、`pageshow` イベントの `event.persisted === true` を検知し、現在の結果見出しの有無を `PAGE_READY` で再通知する。
- DOM 更新を監視する `MutationObserver` は使用しない。SPA 的に同一ドキュメント内で後から結果が出現するケースは対象外とする。
- 同じブラウザセッション内で、同じ結果表示をリロードしただけでは重複カウントしない。
- 結果ページから別のページへ移動して結果表示がいったん非表示になった後、再び結果ページを表示した場合は 1 回加算する。
- URL は結果の識別子として使わない。同じテストで URL が同じでも、結果表示の状態遷移を基準にする。
- 複数タブで別々の結果が表示された場合は、それぞれを加算し、全タブで共有する当日合計にする。
- 100 回未満で結果表示を検知したときだけ、自動カウントを 1 回増やす。

重複防止は、各タブの直前のページ状態をサービスワーカー側で管理する。結果ページの読み込み時に、同じタブの直前状態がすでに結果ページなら加算しない。対象外 URL へ遷移した場合はそのタブ状態をクリアする。

実装を単純にするため、ブラウザ再起動、拡張機能の更新・再読み込み後は重複防止用のタブ状態を引き継がない。その後に復元・再読み込みされた結果ページは、新しい表示として 1 回加算することを許容する。

### 日次リセット

- 日付判定はユーザーのブラウザ／端末のローカル時間を使う。
- 日付キーはローカル時間の `YYYY-MM-DD` とする。UTC 日付を使わない。
- 毎分の `chrome.alarms` で日付変更を確認し、日付が変わっていれば現在カウントを 0 にする。
- サービスワーカー起動時に日次リセット用アラームの存在を確認し、存在しなければ 1 分間隔で再作成する。
- アラームが遅延・停止した場合にも備え、カウンター取得、加算、ポップアップ表示、履歴表示の直前にも日付を確認する。
- 日付変更時も前日以前の履歴は削除しない。ただし 90 日を超えた履歴は削除する。

日次リセットの対象は学習回数カウンターだけとし、実行中または停止中のストップウォッチ状態には適用しない。

### 設定・履歴

- 過去 90 日を保存する。表示範囲は今日を含む直近 90 日（今日＋直近 89 日）とする。
- 90 日を超えたデータは自動削除する。
- 結果表示による自動カウントだけを記録する。開始回数の変更は記録しない。
- 日別一覧には、自動カウントが1回以上ある日だけを表示する。自動カウントが0回の日は、ストップウォッチ停止履歴があっても表示しない。
- 表示対象の日が1日もない場合は、履歴欄に `履歴はありません` と表示する。
- 設定と履歴は 1 つのモーダルへ統合し、カウンターパネルの歯車ボタンから開く。
- 歯車ボタンはアイコンだけを表示し、`title` と読み上げ用ラベルを「設定・履歴」とする。
- 統合モーダルの上部へ設定項目、区切り線の下へ履歴を表示する。
- 設定欄には「1日の目標回数」の数値入力と、将来ほかの設定項目が増えても設定全体を保存する扱いの「設定を保存」ボタンを置く。
- 設定を保存すると、モーダルを開いたままパネルの分母とすべての対象タブへ即時反映する。
- 保存せずにモーダルを閉じた入力内容は破棄し、次回表示時は保存済み設定を読み直す。
- 日別一覧は新しい日付を上に表示し、「日付」「自動カウント回数」を表示する。
- 各日付の自動カウント回数の下に、ストップウォッチを停止した時刻と、その時点の累積経過時間を一覧表示する。
- ストップウォッチ履歴も今日を含む直近 90 日だけ保存し、90 日を超えたデータと一緒に自動削除する。
- 初期実装では、日付ごとの自動カウント数とストップウォッチ停止履歴を保存・表示する。

### 第2段階の任意機能

各タイピング結果の自動カウント日時と `+1` を表示する増加履歴は、初期実装の対象外とする。これはストップウォッチ停止履歴とは別の任意機能である。将来追加する場合も、開始回数の設定操作は増加履歴へ記録しない。追加時はデータスキーマのバージョンを上げ、既存の日別履歴を維持できる移行処理を用意する。

## 3. サンプルから読み取れるデザイン方針

サンプルの結果ページは、[`sample/アクティアイランド.html:343`](../sample/アクティアイランド.html#L343) 付近に `.taipinguResult` と `.title_text-result` があり、「今回のタイピング結果」を表示している。

見た目は、サンプルの次の雰囲気に合わせる。

- 主要文字色：濃い茶色 `#42210B`
- 見出し・枠：茶色 `#8E610D`
- 結果ページの大きな見出しに使われている配色・角丸・太字を参考にする
- 背景はページを隠さない半透明のクリーム／白系
- 補助的な操作ボタンにはサイト内で使われている青系または黄色系を使う

参照箇所：[`sample/アクティアイランド_files/index.css:506`](../sample/アクティアイランド_files/index.css#L506)、[`sample/アクティアイランド_files/index.css:527`](../sample/アクティアイランド_files/index.css#L527)、[`sample/アクティアイランド_files/index.css:1209`](../sample/アクティアイランド_files/index.css#L1209)。

拡張機能の CSS はサイトの CSS へ依存させない。コンテンツスクリプトで Shadow DOM を使い、サイト側の CSS と拡張機能側の CSS の干渉を防ぐ。

カウンターパネル内では、学習回数とストップウォッチを視覚的に分ける。ストップウォッチの経過時間は等幅数字で読みやすく表示し、開始・再開、停止、リセットの有効／無効状態を色と `disabled` 属性の両方で表す。リセット確認モーダルも同じ Shadow DOM 内に作り、「リセットする」「キャンセル」の 2 操作を用意する。

## 4. 推奨構成

ビルド環境を増やさず、Vanilla JavaScript とする。実装開始時の構成は次を基本とする。

```text
manifest.json
background/
  service-worker.js
content/
  content-script.js
popup/
  popup.html
  popup.css
  popup.js
docs/
  implementation-guide.md
```

### `manifest.json`

- `manifest_version`: `3`
- `name`: `アクティカウンター`
- `action.default_popup`: `popup/popup.html`
- `background.service_worker`: `background/service-worker.js`
- `permissions`: `storage`, `alarms`, `webNavigation`
- `host_permissions` は指定しない。
- `content_scripts.matches` は `https://acti-island.com/typing` と `https://acti-island.com/typing/*` だけを指定し、`content/content-script.js` を `document_idle` で注入する。

`tabs` 権限、`<all_urls>`、サイト全体へのホスト権限は使用しない。ページ内容へアクセスするのは、指定 URL に注入されたコンテンツスクリプトだけとする。

### コンテンツスクリプト

担当範囲は次のとおりとする。

1. 対象 URL を確認する。
2. 初期 DOM から結果見出しの有無を判定する。
3. 初期実行時に `PAGE_READY` メッセージで `{ isResult: boolean }` をサービスワーカーへ送る。
4. `pageshow` を監視し、`event.persisted === true` の場合は結果見出しを再判定して `PAGE_READY` を送る。
5. サービスワーカーから現在カウントを受け取り、右上パネルを描画する。
6. 歯車ボタンが押されたら `GET_STATE` と `GET_HISTORY` を要求し、Shadow DOM 内の設定・履歴モーダルを開く。
7. `chrome.storage.onChanged` を購読し、別タブでの加算・ポップアップからの変更・日次リセットを表示へ反映する。
8. ストップウォッチ状態を取得し、開始時刻と保持済み経過時間から 1 秒ごとに表示を更新する。
9. `chrome.storage.session` のストップウォッチ状態変更を購読し、他の対象タブでの開始・停止・再開・リセットを反映する。
10. リセット操作時は Shadow DOM 内に独自確認モーダルを表示し、確認された場合だけサービスワーカーへリセットを要求する。
11. パネルヘッダーの Pointer Events を監視してドラッグ移動させ、ドラッグ終了時に位置を保存する。
12. `chrome.storage.local` の位置変更を購読し、他の対象タブへ保存位置を反映する。
13. 設定フォームを検証して設定全体を `SAVE_SETTINGS` で保存し、`appState.settings` の変更を対象タブへ反映する。

パネルのイベントはサイトへ漏らさない。ボタンのクリックがサイト側のリンクやフォーム操作を発火させないよう、必要に応じて `stopPropagation()` と `preventDefault()` を使う。

### サービスワーカー

担当範囲は次のとおりとする。

- 全タブ共通のカウントと履歴の読み書き
- 日付変更の判定と 0 回へのリセット
- 起動時のアラーム存在確認と、毎分アラームの作成・処理
- タブ単位の結果表示状態の管理
- 全タブ共通のストップウォッチ状態と停止履歴の管理
- コンテンツスクリプト、ポップアップからのメッセージ処理
- すべての状態変更処理の直列化

自動加算、開始回数変更、日次リセット、90 日超過データ削除、タブ状態の確認・更新、ストップウォッチの開始・停止・再開・リセットは、すべて同じ 1 本の Promise キューへ入れる。`chrome.storage.local.get`／`chrome.storage.session.get` から保存までをキュー内で完了させ、同時操作で更新が失われないようにする。複雑なロック機構や再試行処理は追加しない。

ストップウォッチ状態は `chrome.storage.session` に保存する。コンテンツスクリプト間で状態変更を共有するため、サービスワーカー起動時に `chrome.storage.session.setAccessLevel({ accessLevel: "TRUSTED_AND_UNTRUSTED_CONTEXTS" })` を設定する。ページ本体の JavaScript からストレージを直接操作させず、操作要求は必ずメッセージ経由でサービスワーカーに検証させる。

`webNavigation.onCommitted` ではトップフレームだけを扱う。対象外 URL へ遷移したタブの状態をクリアし、対象 URL ではコンテンツスクリプトの `PAGE_READY` を待つ。タブが閉じられたときはタブ状態を削除する。

### ポップアップ

ポップアップには次を表示する。

- 今日の現在カウント
- `開始回数（0〜100）` の数値入力
- `開始回数を保存` ボタン
- 保存成功・入力エラーの短いメッセージ

入力は整数に限定し、0 未満・100 超過・空欄・小数・文字列は保存しない。サービスワーカー側でも同じ範囲を検証する。

保存成功時は現在カウントだけを書き換える。履歴の日別回数は変更しない。

ポップアップにはストップウォッチの表示・操作・設定を追加しない。

## 5. データ設計

カウンターと履歴の永続状態は、将来の拡張に備えて `appState` の 1 キーへまとめる。

```json
{
  "appState": {
    "schemaVersion": 1,
    "current": {
      "date": "2026-08-29",
      "count": 3
    },
    "settings": {
      "targetCount": 10
    },
    "history": {
      "2026-08-29": {
        "autoCount": 3,
        "stopwatchEntries": [
          {
            "stoppedAt": 1787952600000,
            "elapsedMs": 600000
          },
          {
            "stoppedAt": 1787953500000,
            "elapsedMs": 900000
          }
        ]
      }
    }
  }
}
```

補足：`current.count` は開始回数を含む現在表示値、`settings.targetCount` は表示上の目標回数、`history.*.autoCount` は自動検知で増えた回数だけを表す。したがって、開始回数を 30 回に設定した直後は `current.count` が 30 になっても、その日の `autoCount` は 0 のままとする。`stopwatchEntries` は停止日の履歴であり、各要素に停止日時と累積経過ミリ秒を保存する。既存データに `settings` がない場合は、読み込み時に `{ "targetCount": 10 }` を補完して保存する。

パネル位置はカウンター履歴とは更新タイミングが異なるため、独立した `panelPosition` キーへ保存する。

```json
{
  "panelPosition": {
    "left": 1042,
    "top": 16
  }
}
```

座標はビューポート左上を基準とする CSS ピクセル値で、パネル左上の `left` と `top` を保存する。読み込み時に数値を検証し、ビューポート外の値は画面内へ補正する。

タブ状態は履歴データと分離し、`chrome.storage.session` の `tabStates` などへ保存する。

```json
{
  "tabStates": {
    "123": "result",
    "456": "other"
  }
}
```

サービスワーカーが停止・再起動しても同じタブのリロードを重複カウントしないため、タブ状態はメモリだけでなくセッションストレージへ保存する。ブラウザ再起動、拡張機能の更新・再読み込みで状態が失われ、その後の結果表示が 1 回加算されることは、単純な実装を優先するため許容する。

ストップウォッチの現在状態も `chrome.storage.session` に保存する。

```json
{
  "stopwatchState": {
    "isRunning": true,
    "startedAt": 1787953200000,
    "elapsedMs": 600000
  }
}
```

- `isRunning`: 計測中かどうか
- `startedAt`: 現在の開始・再開操作を行った時刻の Unix epoch ミリ秒。停止中は `null` とする。
- `elapsedMs`: 現在の開始・再開より前に確定している累積経過ミリ秒

計測中に表示する値は `elapsedMs + (Date.now() - startedAt)` とする。停止時はこの値を新しい `elapsedMs` として保存し、`startedAt` を `null` にしたうえで、同じ累積値を停止日の `stopwatchEntries` へ追加する。

## 6. メッセージ仕様

メッセージには必ず `type` を付ける。エラー時は `{ ok: false, error: "..." }` を返す。

| type | 送信元 | 用途 | 備考 |
| --- | --- | --- | --- |
| `PAGE_READY` | コンテンツスクリプト | ページ状態を通知 | `isResult` を含む。結果状態への遷移時だけ自動加算 |
| `GET_STATE` | コンテンツスクリプト／ポップアップ | 現在値を取得 | 日付確認後の値を返す |
| `SET_START_COUNT` | ポップアップ | 当日の現在値を即時変更 | 0〜100、履歴は変更しない |
| `SAVE_SETTINGS` | コンテンツスクリプト | 設定全体を保存 | `settings.targetCount` は1〜100の整数 |
| `GET_HISTORY` | コンテンツスクリプト | 90 日分を取得 | 0 回の日も含めて返す |
| `GET_STOPWATCH_STATE` | コンテンツスクリプト | ストップウォッチ状態を取得 | 状態がなければ停止中の 0 秒を返す |
| `START_STOPWATCH` | コンテンツスクリプト | 開始または再開 | 停止中だけ受け付ける |
| `STOP_STOPWATCH` | コンテンツスクリプト | 停止して履歴を保存 | 計測中だけ受け付ける |
| `RESET_STOPWATCH` | コンテンツスクリプト | 累積時間を 0 に戻す | 停止中だけ受け付け、履歴は削除しない |

`PAGE_READY` の処理は次の状態遷移とする。

| 直前のタブ状態 | 今回 `isResult` | 処理 |
| --- | --- | --- |
| なし／`other` | `false` | `other` を保存、加算しない |
| なし／`other` | `true` | 上限未満なら自動加算し、`result` を保存 |
| `result` | `true` | `result` のまま、加算しない |
| `result` | `false` | `other` を保存、加算しない |

ストップウォッチ操作の状態遷移は次のとおりとする。

| 現在状態 | 操作 | 処理 |
| --- | --- | --- |
| 停止中・0 秒 | 開始 | `startedAt` を現在時刻にし、計測を開始 |
| 停止中・1 秒以上 | 再開 | 保持済み `elapsedMs` は変えず、`startedAt` を現在時刻にして再開 |
| 計測中 | 停止 | 累積時間を確定し、停止日の履歴へ新しい 1 件を追加 |
| 停止中 | リセット確認 | 独自確認モーダルを表示し、状態はまだ変更しない |
| 停止中 | リセット確定 | `elapsedMs` を 0、`startedAt` を `null` にする。履歴は変更しない |
| 計測中 | 開始／リセット | 要求を拒否し、状態を変更しない |
| 停止中 | 停止 | 要求を拒否し、履歴を追加しない |

## 7. 設定・履歴モーダルの UI

- モーダルのタイトルは `設定・履歴` とする。
- 上部の `設定` 欄へ、1〜100の数値入力と `設定を保存` ボタンを表示する。
- 保存成功または入力エラーは設定欄内へ短いメッセージで表示し、保存成功時もモーダルを閉じない。
- 設定欄の下を区切り、`過去90日の記録` を表示する。
- 閉じるボタンと、背景クリックまたは `Escape` で閉じる操作を用意する。
- 自動カウントが1回以上ある日だけを対象とし、各行に `YYYY/MM/DD` と `自動カウント: n回` を表示する。
- ストップウォッチ停止履歴がある日は、自動カウント回数の下へ `HH:mm:ss 停止 — 累積 HH:MM:SS` の形式で新しいものから表示する。
- ストップウォッチ履歴がない日は、停止履歴欄を省略するか `記録なし` と表示する。
- 表示対象の日がない場合も空画面にはせず、`履歴はありません` と表示する。
- モーダル表示中に別タブでカウントが増えた場合、履歴は再表示時に最新値を取得すればよい。リアルタイム更新は必須ではない。

## 8. 実装上の注意

- `chrome.storage.local` に保存する前に、日付変更と 90 日超過データの削除を毎回確認する。
- 年月をまたぐ日付計算では `Date` の UTC メソッドを使わず、ローカル日付キーを生成する。
- `appState` と `tabStates` を変更する処理は、日次リセットや履歴削除を含めてサービスワーカーの同一ミューテーションキューで直列化する。
- `stopwatchState` の変更と、停止時の `stopwatchEntries` 追加も同じミューテーションキュー内で完了させる。
- ストップウォッチ表示用の 1 秒タイマーを永続データの加算には使わない。各描画時に `Date.now()` との差分を計算する。
- コンテンツスクリプト破棄時は、表示更新用の `setInterval` を解除する。
- パネルとモーダルは Shadow DOM で隔離し、サイトの `.title`、`.menu`、`button` などの CSS を上書きしない。
- サイトの既存リンク・フォーム・キーボード操作を妨げない。
- ヘッダーのドラッグには Pointer Events とポインターキャプチャを使い、画面外へ移動してもドラッグ終了を検知できるようにする。
- パネル位置はドラッグ中にストレージへ連続保存せず、ドラッグ終了時だけ保存する。
- 目標回数はコンテンツスクリプトとサービスワーカーの両方で1〜100の整数か検証する。
- 設定保存メッセージは個別値ではなく `settings` オブジェクトを受け渡し、将来の設定追加時も同じ保存操作へまとめられる形にする。
- `chrome.runtime.lastError` を確認し、ページを閉じた直後などの送信失敗で拡張機能全体がエラーにならないようにする。
- 外部 CDN、外部 API、リモート画像は使用しない。

## 9. 受け入れ条件

### 基本動作

- [ ] `https://acti-island.com/typing` でパネルが表示される。
- [ ] `https://acti-island.com/typing/595/result` のような配下 URL でもパネルが表示される。
- [ ] `/typing` 配下ではない URL にパネルが表示されない。
- [ ] サンプルと同じ「今回のタイピング結果」の初期表示で 1 回だけ加算される。
- [ ] 同じブラウザセッション内では、同じ結果ページのリロードで増えない。
- [ ] 結果ページから別ページへ移動し、再び結果ページを開くと 1 回増える。
- [ ] Back/Forward Cache から結果ページが復元された場合も、非結果ページからの再表示として 1 回増える。
- [ ] ブラウザ再起動、拡張機能の更新・再読み込み後に復元された結果ページは、新しい表示として 1 回増える。
- [ ] 同じ結果ページを複数タブで開いただけでは、各タブの初回表示がそれぞれ 1 回として扱われる。
- [ ] 100 回に到達した後も 100 回を超えない。
- [ ] 初期状態ではカウンターが `0 / 10回` と表示される。
- [ ] 現在値が目標回数を超えてもカウントが続き、現在値と目標値がそのまま表示される。

### ストップウォッチ

- [ ] 対象ページで初回は右上に表示されるパネルへ、`00:00:00` と開始・停止・リセットボタンが表示される。
- [ ] 開始すると 1 秒ごとに表示が更新され、タブを休止しても実時間との差がずれない。
- [ ] ある対象タブで開始・停止・再開・リセットすると、別の対象タブへ同じ状態が反映される。
- [ ] ページ遷移、対象タブの終了、サービスワーカーの停止後も、Chrome が起動している間は計測を継続する。
- [ ] 停止後はボタンが「再開」になり、保持した累積時間から計測を再開できる。
- [ ] 計測中はリセットできず、停止中にリセットを押すと独自確認モーダルが開く。
- [ ] リセットを確定すると `00:00:00` と「開始」に戻り、キャンセルすると状態が変わらない。
- [ ] 24 時間を超える経過時間も累積した時間数で表示される。
- [ ] Chrome 終了、拡張機能の更新・再読み込み後は `00:00:00` の停止状態になり、未停止時間が履歴へ追加されない。
- [ ] 日付をまたいでも停止まで計測が続き、停止日の履歴へ保存される。

### 日次・開始回数

- [ ] 初期状態が 0 回である。
- [ ] ポップアップから 0〜100 の整数を保存すると、当日の表示が即時にその値になる。
- [ ] 開始回数を変更しても履歴の日別回数が変わらない。
- [ ] ローカル日付が変わると現在値が 0 回になる。
- [ ] 前日の履歴は日付変更後も残る。

### 設定・履歴

- [ ] ヘッダーの歯車ボタンから設定・履歴モーダルを開閉できる。
- [ ] 歯車ボタンに「設定・履歴」のツールチップと読み上げ用ラベルがある。
- [ ] モーダル上部に設定、その下に過去90日の記録が表示される。
- [ ] 1〜100の目標回数を保存すると、モーダルを閉じずにパネルの分母へ反映される。
- [ ] 0、101、空欄、小数、文字列は保存できない。
- [ ] 保存した目標回数が日付変更、ページ遷移、Chrome再起動後も維持される。
- [ ] 保存せずに閉じた入力値は破棄され、次回は保存済みの値が表示される。
- [ ] ある対象タブで保存した目標回数が、別の対象タブへ即時反映される。
- [ ] 今日を含む直近90日のうち、自動カウントが1回以上ある日だけが表示される。
- [ ] 自動カウントが0回の日は、ストップウォッチ停止履歴があっても表示されない。
- [ ] 表示対象の日がない場合は `履歴はありません` と表示される。
- [ ] 停止するたびに、停止時刻とその時点の累積経過時間が停止日の履歴へ追加される。
- [ ] 停止後に再開して再度停止すると、以前の履歴を上書きせず、新しい累積時間の履歴が追加される。
- [ ] リセットしても保存済みのストップウォッチ履歴が残る。
- [ ] ストップウォッチ履歴がない日も、日付と自動カウント回数は表示される。
- [ ] 91 日以上前のデータが自動削除される。

### UI・権限

- [ ] パネルとモーダルがサイトのレイアウトを崩さない。
- [ ] パネルヘッダーをドラッグすると、パネルがマウスポインターへ追従する。
- [ ] 歯車ボタンを押してもドラッグが開始されず、設定・履歴モーダルが開く。
- [ ] パネルを画面端へドラッグしても、パネル全体が画面内に収まる。
- [ ] ドラッグ終了後にページ遷移または Chrome 再起動を行っても、保存位置が復元される。
- [ ] ある対象タブでドラッグを終了すると、別の対象タブへ同じ位置が反映される。
- [ ] ウィンドウを縮小して保存位置が画面外になる場合、パネル位置が画面内へ自動補正される。
- [ ] 複数タブでカウント値が一致する。
- [ ] `host_permissions`、`tabs`、`<all_urls>` を使用せず、権限が `storage`、`alarms`、`webNavigation` と指定 URL の静的コンテンツスクリプトに限定されている。

## 10. 手動テスト手順

1. Chrome の `拡張機能を管理` でデベロッパーモードを有効にし、リポジトリを「パッケージ化されていない拡張機能」として読み込む。
2. 対象サイトの `/typing` と結果ページを別々に開き、パネル表示を確認する。
3. 同じブラウザセッション内で結果ページをリロードし、数値が増えないことを確認する。
4. 拡張機能を再読み込みしてから結果ページを再読み込みし、新しい表示として 1 回増えることを確認する。
5. 非結果ページへ移動してから「戻る」で結果ページへ戻り、Back/Forward Cache が使われた場合も 1 回増えることを確認する。
6. 2 つのタブで結果ページを開き、合計が正しく共有されることを確認する。
7. ポップアップから 0、任意の中間値、100 を保存し、表示値が即時反映されることを確認する。
8. 歯車ボタンから設定・履歴モーダルを開き、上部の設定と下部の履歴を確認する。自動カウントが1回以上ある日だけが表示され、対象日がなければ `履歴はありません` と表示されることを確認する。
9. サービスワーカーを再起動し、日次リセット用アラームが存在しなければ再作成されることを確認する。
10. Chrome DevTools で日付キーを検証できるテスト用の日時注入または単体テストを用意し、日次リセットと 90 日 pruning を確認する。
11. ストップウォッチを開始し、複数の対象タブで同じ経過時間とボタン状態が表示されることを確認する。
12. 対象タブをすべて閉じてから別の対象ページを開き、Chrome を終了していなければ計測が継続していることを確認する。
13. 停止、再開、再停止を行い、累積時間から再開され、停止のたびに別の履歴が追加されることを確認する。
14. 停止中にリセットを押し、独自確認モーダルのキャンセルと確定をそれぞれ確認する。確定後も停止履歴が残ることを確認する。
15. 実行中に拡張機能を再読み込みし、未停止時間が履歴に追加されず、`00:00:00` の停止状態へ戻ることを確認する。
16. テスト用の日時注入で日付をまたいでから停止し、リセットされず停止日の履歴へ保存されることを確認する。
17. パネルヘッダーを上下左右へドラッグし、画面端を越えずに追従することを確認する。
18. 歯車ボタンのクリックでドラッグが始まらず、設定・履歴モーダルが開くことを確認する。
19. ドラッグ終了後にページを再読み込みし、さらに Chrome を再起動して、保存位置が復元されることを確認する。
20. 対象ページを 2 タブで開き、一方のドラッグ終了後にもう一方へ同じ位置が反映されることを確認する。
21. パネルを右下へ移動してからウィンドウを縮小し、パネル全体が画面内へ補正されることを確認する。
22. 初期分母が10回であることを確認し、目標回数を1、任意の中間値、100へ変更して保存する。
23. 無効値を保存できないこと、保存時にモーダルが閉じないこと、別タブへ即時反映されることを確認する。
24. 入力値を保存せずにモーダルを閉じ、再表示時に保存済みの値へ戻ることを確認する。
